## 首条评论（HN 帖无正文，故事写在第一条评论）

> Author here. My son is 3½. I didn't try to teach him to code — I made him web games instead. One game per chapter of Grokking Algorithms:
>
> - Binary search → guess which tree hole the animal hides in (≤7 tries)
> - Selection sort → queue animals for ice cream, shortest first
> - Recursion → open nesting dolls down to the empty one, then count back out
> - Quicksort → pick a pivot book, split the pile, repeat
> - Hash table → tools with big numbers, "take the last two digits = locker number"
> - BFS → tap "expand" and watch friendship waves reach the ice-cream maker
> - Dijkstra → compare step-badges and pick the nearest junction each time
> - Greedy → cover every village with the fewest towers (level 2 has a real trap)
> - DP → pack acorns into a fixed-size basket for max value
> - KNN → pick K nearest neighbors on a feature map and vote
>
> All plain HTML/CSS/JS, zero dependencies, zero install — click a link on GitHub Pages and it runs. Every game's core logic is pure and unit-tested (my Dijkstra must match brute-force enumeration on random graphs). Each game also has a Playwright smoke test that plays the whole flow like a kid would.
>
> The educational part: each algorithm has a "parent-child trio" — a bedtime story, a printable offline activity card, and the web game. I also keep a public weekly log of what actually happened when we played (first episode: he tapped the tree holes himself, 5/5 happiness).
>
> It's CC BY-NC licensed (free for families/education) and has good-first-issue tasks if you want to help: add a mute button, translate the README, compatibility-test on WeChat's browser, etc.
>
> The honest pitch: this isn't a product, it's a 15-year father-son project that happens to be open source. If you have a 3-7yo, the most useful thing is the activity cards PDF (print & play) — no screen required.
