# 选择排序 · 教给别人版

## 给 8 岁孩子讲的版本

> 全班 30 个人要按身高排座位。老师怎么排最快？
> 最简单的办法：**先找最矮的，让他坐第一排；再在剩下的人里找最矮的，坐第二排……**
> 一直挑到没人剩。这就是"选择排序"——每次选一个最小的，放好。
> 30 个人要挑 30 次，每次都要把剩下的人从头看一遍。

## 给大人讲的版本

- **核心思想**：重复做两件事——① 在剩余元素中找最小；② 放到已排序区末尾
- **复杂度**：O(n²)。n 个元素挑 n 次 × 每次扫 n 个 = n²/2 次比较
- **实测**：n 翻倍 → 时间 ×4（平方爆炸）；内置 sorted() 只 ×2（O(n log n)）。8000 个元素：5.6 秒 vs 1.6 毫秒
- **应用**：没人真的用它排序大数组——**它存在的意义是教你"算法复杂度"这个概念**。它是第一个让你感受 O(n²) 的算法

## 代码逐行（solution.py 原地版）

```python
for i in range(n):              # i 是已排序区边界：前 i 个已排好
    min_idx = i                 # 假设 i 位置就是最小的
    for j in range(i + 1, n):   # 扫一遍剩余区 [i+1, n)
        if arr[j] < arr[min_idx]:
            min_idx = j         # 发现更小的，记下来
    arr[i], arr[min_idx] = arr[min_idx], arr[i]  # 交换到正确位置
```

## 两个经典坑

1. **`min_idx` 必须从 `i` 开始，不是从 `0`**——否则会把已排好的部分又翻出来比（功能还行，但白干活；最坏情况会重复交换，效率 ×2 的浪费）
2. **交换是"值和索引"分开记**——先记下标，全部扫完再交换；边扫边换会破坏"找最小"的逻辑

## 对比全家桶（本书第 1-2 章核心收获）

| 算法 | 复杂度 | 类比 | 一句话 |
|------|--------|------|--------|
| 二分查找 | O(log n) | 猜数字砍半 | 有序数据 + 砍半 = 指数加速 |
| 选择排序 | O(n²) | 挑最矮排座位 | 简单粗暴，n² 爆炸 |
| （预告）快排 | O(n log n) | 分而治之 | 第 4 章的地基 |

## 一句话总结

> **选择排序不重要，O(n²) 很重要。** 它教会你两件事：复杂度怎么算（n²/2 次比较）、以及为什么"简单"不等于"快"——这也是将来学快排、归并时对比的基准线。
