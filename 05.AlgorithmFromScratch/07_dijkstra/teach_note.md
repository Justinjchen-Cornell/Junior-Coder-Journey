# Dijkstra 算法 · 教给别人版

## 给 8 岁孩子讲的版本

> 从家到学校有三条路：一条直达但要 100 块钱打车，一条绕一下只要 4 块钱。
> "段数最少"的路不一定最便宜！
> 聪明的办法：兜里带一块**最低价面板**。每到一站，看面板上哪个数字最小，
> 就去那一站——每去一站就问问自己："从这出发，能不能让面板上的数字变得更小？"
> 一直问到终点，面板上终点的数字就是**最便宜的价格**。
> 记住：**每一站只去一次**（去过了就把它的数字定下来），因为绕回去只会更贵。

## 给大人讲的版本

- **问题**：带权图（每条边有代价）上找"总代价最低"的路径
- **贪心核心**：每次选"当前代价最小且未定案"的节点处理——非负权值保证它已经是最优，不会再有更便宜的路经过它
- **与 BFS 的关系**：BFS = Dijkstra 的特例（所有权值 1）；Dijkstra = 用优先队列替换普通队列的 BFS
- **两种实现**：
  - 表格法（书式）O(V²)：每次线性扫一遍找最小——思路直白
  - 堆优化 O((V+E)logV)：小根堆弹出最小——工程标准
- **实测**（benchmark.py）：
  - BFS 在带权图选错路（1 段 100 块 vs 2 段 4 块）
  - 5000 节点：表格法 4035ms vs 堆优化 32ms（**126 倍**）
  - 负权翻车两场景（见下）
- **负权值 = 命门**：贪心"定案"在负权下不成立 → Bellman-Ford（可检测负环——**外汇套利的三角/多角套利检测就是这个**）

## 代码逐行（solution.py 表格法核心）

```python
while True:
    # 1) 从"未定案"节点里挑代价最小的（贪心：它已是最优，不会更便宜）
    node = argmin({n: costs[n] for n in costs if n not in processed})
    if node is None: break
    # 2) 松弛：从它出发，看能否让邻居的代价更小
    for nb, w in graph[node].items():
        if costs[node] + w < costs[nb]:
            costs[nb] = costs[node] + w    # 更新面板
            parents[nb] = node             # 记下"怎么来的"
    processed.add(node)                    # 3) 定案：它永不再被更新
```

## 三个经典坑

1. **负权值**：贪心定案的前提是"非负"——负边会让已定案的节点其实还能更便宜（实测：表格版路径和代价自相矛盾）
2. **提前退出 vs 全部处理**：找到终点就 break 可以（堆版），但如果存在负边直达终点，提前退出会漏掉更优解
3. **邻接表要 get 默认空**：图里不是每个节点都有 key（如终点），`graph[node]` 会 KeyError

## 生活应用

- 地图导航（百度/高德的路权 = 边权）、网络路由协议（OSPF 就是 Dijkstra）
- **外汇套利**：货币对汇率 = 边权（取负对数），负环检测 = Bellman-Ford —— 你的领域直接相关
- 游戏寻路（A* 是 Dijkstra + 启发式）

## 一句话总结

> **Dijkstra = 贪心 + 松弛 + 定案**，前提是"路不会越走越便宜"（非负权）。
> 它是 BFS 的有权版、A* 和 Bellman-Ford 的兄弟——图算法家族的核心成员。
