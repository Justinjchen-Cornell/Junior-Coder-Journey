# 贪心算法 · 教给别人版

## 给 8 岁孩子讲的版本

> 分糖果的时候，每次都先拿"最大的那一把"——这就是贪心（贪心 = 贪眼前）。
> 有时候很聪明：比如安排开会，每次都先安排"结束最早"的那个会，后面就能塞进最多的会——**每次都赢**。
> 但有时候会吃亏：比如买拼图组合，贪心先拿最大的那盒，结果发现小的两盒合起来更划算——**贪心不一定赢**。
> 聪明人先搞清楚：这个问题"贪心能不能赢"？不能赢的时候，就接受"差不多就好"。

## 给大人讲的版本

- **贪心 = 每步选局部最优，期望全局最优**
- **两类命运**：
  - ✅ **活动选择（会议室）**：按结束时间排序 + 先选结束最早的 = **可证明最优**（每次都给后面留最多时间，数学归纳）
  - ⚠️ **集合覆盖（广播台）**：每次选覆盖最多的 = **近似**（实测平均 1.01x，最坏 ln n，且构造实例会翻车：贪心 2 组 vs 最优 1 组）
- **为什么集合覆盖难**：它是 **NP 完全**——最优解要枚举 2^n 种组合（每多一个候选，工作量翻倍）；n=30 就要 10 亿种
- **工程哲学**：NP 完全问题 → 不追求最优，追求"足够好 + 可证明的近似界"（近似算法）
- **识别 NP 完全的口诀**（书中）：
  - 元素少但组合爆炸（子集类问题）
  - 涉及"所有组合"（排列类问题：旅行商）
  - 元素一变就要重算所有方案
  - 可以归约到集合覆盖或旅行商

## 代码逐行（solution.py 核心）

```python
def greedy_set_cover(universe, sets):
    remaining = set(universe)            # 还没覆盖的
    while remaining:
        # 贪心决策：谁的"新增覆盖"最多就选谁
        best = max(sets, key=lambda n: len(sets[n] & remaining))
        remaining -= sets[best]          # 标记已覆盖
        chosen.append(best)
    return chosen
```

```python
def greedy_activity_select(activities):
    last_end = -inf
    for s, e in sorted(activities, key=lambda a: a[1]):   # 按结束时间排序
        if s >= last_end:                # 不冲突就选（结束最早的先选）
            chosen.append((s, e))
            last_end = e
    return chosen
```

## 金融/交易类比（爸爸的领域）

- **贪心 = 每次都抓眼前最大机会**：短线高频的打法，局部漂亮但可能错过全局最优（类似集合覆盖翻车）
- **活动选择 = 时间管理的最优解**：先做"结束最早"的任务（番茄钟、紧急不重要矩阵的贪心版）
- **NP 完全 = 全市场最优配置**：组合优化（最优投资组合、最优路径）本质都是 NP——所以量化里"近似+启发式"是常态，和这里同一个道理

## 一句话总结

> **贪心不是一种算法，是一种策略**——它的价值在于：① 可证明最优的问题（活动选择）直接用；② NP 完全的问题（集合覆盖）用它做近似。**识别"这个问题能不能贪心"比会写贪心更重要。**
