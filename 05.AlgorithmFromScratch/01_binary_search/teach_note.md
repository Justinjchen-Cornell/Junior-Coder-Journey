# 二分查找 · 教给别人版

## 给 8 岁孩子讲的版本

> 玩过"猜数字"吗？我说一个 1~100 之间的数，你猜，我告诉你"大了/小了"。
> 傻瓜猜法：从 1 猜到 100，运气不好要猜 100 次。
> 聪明猜法：**永远猜中间**。猜 50，说"小了"，那 1~50 全部作废，只在 51~100 里猜，再猜 75……
> 每次猜完，可能范围就**少一半**。1~100 最多猜 7 次，1 个亿也只要 27 次。
> 这个"每次都把问题砍半"的招，就叫**二分查找**。

## 给大人讲的版本

- **要解决的问题**：在**有序**数据里找东西（查字典、查通讯录、数据库索引）
- **核心思想**：每次比较中点，排除一半不可能的范围 —— 指数级压缩
- **前提条件**：数据必须有序（这是命门，无序数组不能二分）
- **复杂度**：O(log n)。100 万条数据只要 ~20 步，线性查找要 100 万步（实测：0.05ms vs 472ms）

## 代码逐行（对应 solution.py）

```python
lo, hi = 0, len(arr) - 1    # 搜索范围：闭区间 [lo, hi]
while lo <= hi:             # 范围非空就继续（lo == hi 时还有一个元素要查）
    mid = (lo + hi) // 2    # 中点（整数除法砍半）
    if arr[mid] == item: return mid   # 命中
    if arr[mid] < item: lo = mid + 1  # 中点偏小 → 右半边 [mid+1, hi]
    else:                 hi = mid - 1  # 中点偏大 → 左半边 [lo, mid-1]
return None                # 范围空了 → 不存在
```

## 三个经典坑（考试必考，踩过才算懂）

1. **`mid = (low+high) // 2` 的 `//` 不能丢**——丢了的版本跑得"对"但慢 10000 倍（本目录实测数据），因为它退化成线性扫描
2. **`while lo <= hi` 是 `<=` 不是 `<`**——否则单个元素（lo==hi）的情况会漏查
3. **`lo = mid + 1` / `hi = mid - 1` 必须 ±1**——如果写 `lo = mid`，两个元素时会死循环（永远砍不掉最后那个）

## 生活应用（讲给孩子听）

- 猜价格游戏（《价格猜猜猜》综艺的算法内核）
- 微信通讯录搜索、字典查字、书籍目录查找
- 游戏里"猜我的生日/星座"小程序

## 真实场景（它在哪工作）
- 🏠 生活：查字典先翻中间、猜商品价格、"按姓氏二分找人"
- 💻 互联网：`git bisect` 二分定位 bug 提交；数据库 B+ 树索引的核心；日志按时间二分查事故点
- 💰 金融：IRR 与期权隐含波动率都是"方程求根"→ 二分/牛顿迭代收敛；利率曲线插值
- 🎮 游戏：排行榜二分插入、存档查找

## 局限性（它做不到什么）
- 前提是"有序"——无序数据要先排序，小数据时排序成本可能吃掉二分收益
- 只能回答"在不在/在哪"，不能回答"最接近的是谁"（需变形）
- 频繁插入/删除的有序数据 → 维护成本高 → 该用平衡树（红黑树）
- 大数场景注意 (lo+hi)//2 的溢出 → 写 lo+(hi-lo)//2

## 一句话总结

> **有序 + 砍半 = 指数级加速。** 二分查找是"用有序性换速度"的第一个算法，也是递归、快排、二叉搜索树的地基。
