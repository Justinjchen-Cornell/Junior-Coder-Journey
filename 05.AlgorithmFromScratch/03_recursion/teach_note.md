# 递归 · 教给别人版

## 给 8 岁孩子讲的版本

> 俄罗斯套娃：打开最大的娃娃，里面是**小一点的同一个娃娃**，再打开，还是……
> 直到打开最小的那个——里面什么都没有了，游戏结束。
> 递归就是"套娃思维"：**解决一个问题 = 先解决它"小一号"的自己**。
> 但必须有一个"最小的娃娃"（基线条件），否则套娃永远打不完，程序就崩了。

## 给大人讲的版本

- **递归 = 函数调用自己** + **基线条件**（保证停下来的出口）
- 两个要素缺一不可：
  - **基线条件（base case）**：最简情形直接给答案，不递归
  - **递归条件（recursive case）**：把问题缩小一格，调用自己
- **代价实测**（benchmark.py）：Python 递归深度上限 1000；忘了基线条件 → `RecursionError`（Python 兜底，C/JS 直接崩栈）
- **使用原则**：递归赢在**表达清晰**（分治/树/图遍历），但**性能未必**——每次调用都压栈

## 代码逐行（solution.py）

```python
def factorial(n):
    if n <= 1:              # 基线条件：1! = 0! = 1
        return 1
    return n * factorial(n - 1)   # 递归条件：n! = n × (n-1)!
```

执行过程（n=3）：
```
factorial(3) = 3 × factorial(2)
            = 3 × 2 × factorial(1)
            = 3 × 2 × 1        ← 触底，开始"回溯"逐层返回
            = 6
```

## 两个经典坑（实测演示过）

1. **忘了基线条件** → 无限递归 → `RecursionError`（Python）/ 栈溢出崩溃（C/JS）
2. **深度太大** → 默认上限 1000 层（`sys.setrecursionlimit` 可以调，但治标不治本；真的大深度要用迭代/尾递归）

## 真实场景（它在哪工作）
- 🏠 生活：文件套文件夹（目录树）、洋葱/套娃、家谱
- 💻 互联网：JSON/XML 嵌套解析、HTML DOM 遍历、编译器语法树、爬虫递归抓链接
- 🧬 生物/分形：科赫雪花、L-系统植物生长、分形山脉
- 💰 金融：股权/基金母子结构穿透层级、复利递推

## 局限性（它做不到什么）
- 深度受限：Python 默认 1000 层 → 栈溢出（C/JS 直接崩）
- 每次调用压栈有开销：递归清晰 ≠ 性能好，大循环用迭代
- 容易重复计算：朴素斐波那契 = 指数级浪费 → 该用 DP 记忆化
- 难调试：调用栈深、报错信息晦涩

## 一句话总结

> **递归是"把问题缩小一格"的思维工具**——它自己不怎么干活，但它是分治、快排、树、图的地基。学不会递归，后面全是空中楼阁。
