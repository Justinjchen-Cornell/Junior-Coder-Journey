# 03 递归 · 亲子课堂

## 🎯 一句话本质
**大问题 = 小一号的自己 + 一个"最小的娃娃"（基线条件）。**
（没有最小的娃娃，就会永远套下去——程序就崩了。）

## 🧒 3岁 · 睡前故事版（1 分钟）

> 妈妈带回来一个俄罗斯套娃。打开最大的，里面还有一个！
> 再打开，还有一个！再打开……越来越小，越来越小……
> 打开到最小的那个——哇，里面**什么也没有了**。
> 最小的娃娃就是"结束的信号"：套娃们知道，到底了，该往回走了。
> 一个、两个、三个……一共五层！
> 要是最小的娃娃里面还有一个更小的，还有一个更小的……
> 那就永远打不完了，就像妈妈讲故事讲到天亮也讲不完！🌙

**讲完问一句**：宝宝，套娃什么时候才算打开完呀？（最小的那个里面空了的时候）

## 🎨 5-7岁 · 动手游戏版（5 分钟）

**游戏：倒着数 + 套娃**
1. 真套娃（或叠叠杯/收纳盒）摆一排，让孩子一层层打开数数
2. 讲"数数的小魔法"：数 5 个套娃 = 打开 1 个 + 数剩下的 4 个；数 4 个 = 打开 1 个 + 数剩下的 3 个……
3. 让孩子发现：**每一次"数 N 个"都在做同一件事，只是数字小一号**
4. 画一棵树：树干分两枝，每枝再分两枝……这就是"递归的画"（分形！）
5. 故意玩一次"没有底的套娃"：数数到 0 了还说"再数"——让爸爸学机器人卡住，孩子哈哈大笑（这是"爆栈"的最直观体验）

## 👨 爸爸版 · 通俗详解

- **直觉**：套娃/剥洋葱/照镜子（镜子里还有镜子）
- **两个要素缺一不可**：基线条件（最小娃娃，直接给答案）+ 递归条件（把问题缩小一格，调用自己）
- **代价实测**：Python 递归深度上限 1000——`factorial(1500)` 直接 RecursionError；忘了基线条件 = 无限递归（Python 会拦，C/JS 直接崩栈）
- **代码直觉**（solution.py）：
  ```python
  def factorial(n):
      if n <= 1: return 1              # 基线：最小的娃娃
      return n * factorial(n-1)        # 递归：n! = n × (n-1)!
  ```
  执行 `factorial(3)`：3×[2×[1]]——先一路"钻进去"，触底后一路"算回来"
- **递归 vs 循环**：递归赢在"表达清晰"（树的遍历、分治、迷宫），循环赢在性能。**先学会递归思维，再谈优化**
- **应用**：文件目录遍历、网页链接爬取、分形图形、快排（下一章全靠它）
- **和小宥宥的连接**：5 岁时玩"倒着数"游戏打底——8 岁学递归时他会觉得"这不就是套娃嘛"

## 🎯 亲子验收题
1. 套娃没有"最小的空娃娃"会怎样？（永远打不完 = 程序爆栈）
2. 数 3 个套娃要"打开几次+数几次"？（打开 1 次，数 2 个——递归条件；数到 1 直接结束——基线条件）
